02 / Study design

An interpretable experiment.
Not a black box.

One molecular structure enters the pipeline; three molecular parameters emerge. We examine whether their errors are acceptable after they pass through the EOS.

RESEARCH QUESTION

Can simple structure-derived descriptors reproduce pure-component vapor–liquid equilibrium through learned PC-SAFT parameters?

A molecule is represented by its SMILES structure. Its published fitted PC-SAFT parameters are supervised labels, and FeOs calculates saturation properties from those predicted parameters.

Prediction-time information: molecular structure only, not measured saturation pressures, liquid densities or reference parameters.

05 / Scientific findings

Evidence before
easy conclusions.

The purpose is to understand what worked, where it failed, and why physical properties behave differently from ML parameter errors.

01

A simpler model can give better vapor pressure.

Ridge + 5 achieved 16.22% development pressure APE versus 25.91% for Extra Trees + 156. Parameter-level improvements did not translate directly to lower EOS pressure error.

02

Density and pressure reward different parameter combinations.

Ridge + 12 reached 1.79% development liquid-density error, while Ridge + 5 gave lower pressure error. A single “best model” depends on the property of interest.

03

The nonlinear learner shows a training–validation gap.

Extra Trees fits training targets closely but its validation errors rise substantially. It still beats Ridge on individual parameter MAEs on that split. The VLE comparison remains a separate test.

LOCAL PRESSURE SENSITIVITY

Small parameter changes, large pressure effects.

Five development molecules were perturbed ±1% in each PC-SAFT parameter. The resulting derivatives suggest sensitivity to dispersion energy and potential cancellation or reinforcement among parameter errors. These are local approximations, not causal proof.

Sensitivity measurements become available after the export.

06 / Reproducibility

Every conclusion
needs a trail.

Source data, preprocessing, model selection and the one-time final held-out evaluation should be inspectable, not just asserted.

01

Data and filtering

Esper2023 parameters from the FeOs repository. Retain saturated, nonassociating C/H-only molecules with 3–20 carbon atoms. Canonicalize SMILES and remove duplicate structures.

Explore source collection ↗
02

Preprocessing

Generate descriptors using RDKit. Apply median imputation and scaling inside a scikit-learn pipeline fitted exclusively on the appropriate training data.

Features: molecular weight, carbon count, rings, rotatable bonds, branch points.

03

Model selection

Evaluate mean baseline, Ridge, Random Forest and Extra Trees. Compare parameter errors using three-fold training-only CV and VLE performance using a separate development split.

Frozen choice: Ridge(alpha=1.0), 5 descriptors.

04

Final evaluation

Refit selected Ridge on the 155 original training molecules. Evaluate exactly once on 39 held-out molecules at four reference-defined temperatures each. Report all failures and extreme errors.

156/156 reference and ML state comparisons converged.

What this project does not claim

No experimental property accuracy is claimed from the reference-PC-SAFT comparisons. No mixtures, polar/association terms, live browser inference or end-to-end differentiable thermodynamic training were used.

Reproduction notes

07 / QUESTIONS BEHIND THE MODEL

Questions worth asking.
Answers we can defend.

Why this model, how it was evaluated, and what its results actually mean.

METHODOLOGY Q&A
THE KEY DISTINCTION

We chose the final model using development-set downstream VLE error, not simply the error in each PC-SAFT parameter. The 39-molecule final test set was kept separate from model selection.

See the model comparisons ↗

01 Features & model choice

01Did we use principal component analysis (PCA)?+

No PCA was used in the final predictor. We retained five original, interpretable RDKit descriptors rather than replacing them with principal components. PCA could be tested in future work, but a high-variance input direction is not necessarily the most useful direction for predicting VLE properties.

02Were the molecular descriptors standardized?+

Yes, for Ridge regression. Descriptors have different numerical scales, so standardization helps make its regularization meaningful. The training-fold mean and standard deviation are learned inside the model pipeline and then applied to validation data; the test set must never be used to fit these transformations. Tree models do not generally require feature standardization.

03Which five features does the final model use?+

Molecular weight, carbon count, ring count, rotatable-bond count and branch-point count. Each is calculated from the molecule's SMILES structure. The final Ridge model predicts the PC-SAFT parameters m, σ and ε/k from these descriptors.

04Why choose Ridge with only five features?+

The five-descriptor Ridge model gave 16.22% development pressure MAPE, compared with 17.96% for Ridge using 12 descriptors. It also used fewer, easier-to-explain inputs. Five was the best choice among the relevant configurations evaluated, not a universal optimum.

05Why did Extra Trees with 156 features have higher pressure error?+

Extra Trees with 156 features produced 25.91% development pressure MAPE, despite strong results on some individual parameter metrics. With a relatively small dataset, many correlated or weakly informative features can increase model variance, and the observed training–validation gap suggests overfitting. In addition, PC-SAFT combines parameter errors nonlinearly. These are plausible explanations, not proof of a single cause. The comparison changes both the algorithm and the feature count.

02 Evaluation & limitations

06Could more than five features reduce the error?+

Possibly. More features can improve training fit while worsening validation performance. We compared several representations, including 5, 12, 28 and 156 features; the tested larger configurations did not give a better selected downstream pressure result. A different subset or carefully validated PCA approach might help, but it must be chosen using training/development data, not the frozen final test.

07How did we avoid data leakage?+

We split by molecule, reserving 39 of 194 curated hydrocarbons for final testing. Model comparisons and preprocessing fits were performed using the other 155 molecules, with cross-validation inside that pool. The final test was used for reporting, not for picking a new model. A random molecule split can still place chemically similar structures on both sides, which is a limitation.

08Does the 20.54% pressure error measure experimental accuracy?+

No. The frozen test gave 20.54% pressure MAPE and 2.66% saturated-liquid-density MAPE relative to FeOs/PC-SAFT calculations with published fitted parameters. These are not comparisons with independently measured experimental VLE data. The 156 tested states correspond to four temperatures for each of 39 molecules.

09Why was pressure harder to predict than liquid density?+

Saturation pressure can respond strongly and nonlinearly to combined errors in the PC-SAFT parameters. Our local sensitivity analysis on five development molecules suggested particular sensitivity to dispersion energy and segment number. Parameter errors may reinforce or partly cancel. That supports a possible mechanism, but does not establish a universal explanation.

10What are the main limitations and next steps?+

The dataset contains only a limited class of nonpolar hydrocarbons. The temperature grid relies on the reference model's critical temperature, and the evaluation does not establish experimental VLE accuracy. Strong next steps would be external experimental validation, structure-aware split tests, uncertainty estimates, and development-only comparisons of alternative feature sets.
